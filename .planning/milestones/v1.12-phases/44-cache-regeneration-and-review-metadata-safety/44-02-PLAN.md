# Plan 44-02: Review Sidecar Preservation and Legacy Cache Metadata Checks

## Scope

Ensure manual audio review does not break call-ready metadata, and lock response
cache metadata checks across both direct lookup and classifier lookup paths.

## Files

- Modify: `saymo/commands/core.py`
- Modify: `saymo/analysis/response_cache.py` if tests expose a gap
- Add/modify tests:
  - `tests/test_review_metadata.py`
  - `tests/analysis/test_response_cache.py`

## TDD Tasks

1. RED: Add test for a review-save helper that overwrites a prepared WAV and
   writes a current `.meta.json` sidecar.
2. RED: Add test that an existing sidecar's sanitized source fields
   (`source_kind`, `source_profile`, `source_sha256`) are preserved during
   review-save when present.
3. Implement helper in `saymo/commands/core.py`, for example
   `_write_reviewed_audio_cache(...)`.
4. Wire `saymo review` to call that helper instead of writing the WAV directly.
5. RED/GREEN: Add response-cache tests proving:
   - `lookup()` refuses a stale cached WAV when `voice_metadata` is configured.
   - `get_variant_by_key()` refuses a stale cached WAV when `voice_metadata` is
     configured.
6. Implement response-cache changes only if the new tests fail.

## Verification

```bash
uv run pytest tests/test_review_metadata.py tests/analysis/test_response_cache.py -q
```

## Safety

- Review-save metadata contains hashes and engine/profile metadata only.
- No raw reviewed text, prompt text, response text, or audio bytes are written
  into sidecars.
